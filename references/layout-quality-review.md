# v0.3.2 — 다이어그램 배치·연결선 개선

## 실제 수정

| 사례 | 이전 v0.3.1 | 이번 v0.3.2 |
|---|---|---|
| 로드밸런서 | 곡선 분기와 별도로 샘플링한 이동 경로; 좁은 화면의 경로 중복 | 동일 크기·등간격 서버, 중앙 LB·DB, 직선 분기. 좁은 화면은 양쪽 공유 레인을 한 번만 그리고 분기점 명시 |
| 이벤트 루프 | 요청·응답 높이가 달라 휘어진 연결; I/O의 큰 곡선 복귀 | 입력·루프·응답을 같은 축에 배치. I/O는 직선 위임 및 직교 복귀. 원형은 루프 내부 의미에만 사용 |
| 파이프라인 | 단계 크기·간격이 제각각이고 대기 블록이 연결선 근처에 흩어짐 | 처리 노드와 대기 공간의 크기·간격 통일. 연결선을 노드 경계에서 끊고 같은 축으로 연결. 좁은 화면은 동일 순서의 세로 배치 |

선과 점에 따로 좌표를 쓰지 않습니다. 하나의 Route 좌표열에서 SVG 선과 CSS 이동
경로를 함께 생성합니다. 공유 레인은 실제로 그려진 부분의 합집합 위를 따라가는지
검사합니다. 회전 궤적은 이벤트 루프의 의미를 나타내므로 유지했습니다.

기본 속도 1.25배(18초 기준 14.4초), 일시정지·다시보기·전체 장면·움직임 줄이기·인쇄
처리는 보존했습니다. 갤러리의 이전판 비교는 원본 사이트가 아니라 전달했던 v0.3.1입니다.

## 보존 범위

세 사례의 수치 모델을 그대로 유지했습니다. 나머지 16종은 동일 입력·접두사·속도에서
매크로 바이트가 이전 v0.3.1과 같습니다. 따라서 이번 수정이 모든 사례의 레이아웃을
고쳤다고 표현하지 않습니다. 앞으로는 references/diagram-layout.md를 공통 작성 기준으로
사용합니다.

## 검사와 제한

단위 검사 54개, 19종 매크로 lint 및 Chromium 회귀 검사와 별도의 3종 경로 일치 검사를
실행했습니다. 넓은 화면과 390/320px에서 이동 중인 점의 중심이 실제 선에 있는지,
표시 중인 라벨이 겹치지 않는지, 폭을 바꿔도 재생 시점이 유지되는지 확인했습니다.
수치와 최대 경로 오차는 tests/layout-verification.json에 기록합니다.

로컬 화면을 검수했지만 원본 사이트와의 실시간 A/B, 실제 Confluence 게시, 다른
브라우저와 FPS는 미검증입니다. 단위 테스트 수나 파일 크기를 품질 점수로 쓰지 않습니다.
이번에는 경로 메타데이터와 모바일 표현이 추가되어 일부 매크로 파일은 더 커졌습니다.

## 재현

```sh
python -m unittest discover -s tests -v
python scripts/build_monitoring_suite.py --baseline /path/to/v0.3.1/cases
python tests/browser_monitoring.py
python tests/browser_diagram_layout.py
```

마지막 검사는 이전판이 포함된 갤러리를 요구합니다. baseline 없이 빌드하면 현재판만
포함되며 비교 버튼은 비활성화됩니다. 미리보기와 배포 매크로를 따로 구현하지 않습니다.
